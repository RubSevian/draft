# MEVIUS2: от редактирования модели до проверки нагрузки и нагрева

Рабочий цикл:

**Модель → проверка → обучение → испытание контроллера → запись нагрузки →
расчёт температуры → сравнение вариантов → изменение модели или контроллера.**

Обучение тоже происходит в симуляции. На этом этапе алгоритм многократно
пробует управлять роботом и сохраняет веса контроллера. Просмотр после обучения
запускает уже сохранённый контроллер с выбранной моделью.

Температура сейчас вычисляется **после записи нагрузки отдельной командой**.
Она ещё не отображается в окне симуляции и не влияет на доступный момент мотора.
Это расчёт эффективной температуры модуля, а не показание физического датчика.

## 0. Подготовка — один раз

Все команды выполняются из папки форка:

```bash
cd "/home/ruben/Desktop/RAS/Robot dog/draft"
```

В этой копии `.venv` и пакеты уже установлены. Для новой копии:

```bash
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -e ".[editor,dev,rl]" mjviser matplotlib -c constraints.txt
.venv/bin/python -c "import torch; print(torch.cuda.is_available())"
```

Последняя команда должна вывести `True`. Для обучения нужна NVIDIA GPU;
редактор и расчёт температуры работают на CPU. Все следующие команды используют
`.venv/bin/python`; активировать окружение отдельно не требуется.

## 1. Редактирование модели

Откройте работающий редактор: **http://localhost:8081**.
Для самостоятельного запуска в терминале:

```bash
.venv/bin/python scripts/robot_tuner.py --port 8081 --viser-port 8080
```

Если уже работает служба `draft-editor`, используйте её или предварительно
остановите её командой `systemctl --user stop draft-editor`, чтобы не запускать
два редактора. Терминал ручного запуска должен оставаться открытым.

Выберите **mevius2** в верхней строке, затем измените:

- **Link Lengths / Geometry** — длины и геометрию;
- **Motor Classes** — назначение классов L/M/S суставам;
- **Actuator design** — момент, скорость и передаточное отношение;
- параметры плотности/массы, которые доступны в исходной схеме Draft.

В **Expressions & Text** поле `L_motor` содержит имя вроде `RS03`.
Имя и явные числовые параметры — отдельные настройки: смена одного имени
не заменяет автоматически уже заданные момент/скорость/редуктор.
Каталоговая справка в таблице показывает параметры серийного мотора;
расчётные значения описывают редактируемый вариант.

Нажмите **Generate**, дождитесь успешной генерации и проверьте отчёт.
**Generate** обновляет папку, выбранную в **Folder**.
**Save…** с именем `v2` сохраняет вариант в `generated/mevius2_v2/`.

Результат этапа: папка модели с `mevius2.xml`, геометрией и
`parameters_from_gui.yaml`. Это описание конструкции, а не обученные веса.
Кнопка **Simulate** в редакторе запускает пассивную физику.

## 2. Связать модель с запуском и проверить управление

В `experiments/mevius2.yaml` указаны:

```yaml
run_name: mevius2_flat
env_kwargs:
  robot_xml: generated/mevius2/mevius2.xml
```

Это именно путь к модели, которая будет обучаться и проигрываться.
Если сохранён вариант `v2`, создайте копию конфигурации, например
`experiments/mevius2_v2.yaml`, и поменяйте в ней оба значения:
`run_name: mevius2_v2_flat` и путь `generated/mevius2_v2/mevius2.xml`.
Во всех последующих командах используйте конфигурацию этого варианта.

Проверка текущей базовой модели:

```bash
.venv/bin/python scripts/check_robot_rollout.py --config experiments/mevius2.yaml
```

Она выполняет 500 шагов с нулевыми действиями вокруг исходной стойки и проверяет
численные значения нагрузки. `PASS` подтверждает работу среды; число сбросов
показывает, сколько раз эпизод начался заново. Такая проверка ещё не доказывает
устойчивую ходьбу. Её запись находится в `logs/mevius2_check/motor_trace.npz`.

Сохраняйте модель, YAML запуска и веса контроллера как согласованный комплект.
Не перезаписывайте обученный вариант редактированием: сохраните следующий через
**Save…**. Изменение модели не обновляет уже обученный контроллер автоматически.

## 3. Обучение контроллера

```bash
.venv/bin/python scripts/train.py --config experiments/mevius2.yaml
```

Текущая конфигурация: 256 параллельных экземпляров, 1000 итераций, локальное
логирование. Алгоритм учится следовать командам движения, удерживать корпус и
работать в пределах модели моторов. Конструкция при обучении не меняется.

Результаты появляются в:

```text
logs/mevius2_flat/<дата-время>_mevius2_flat/
  model_0.pt
  model_50.pt
  ...
  model_999.pt
  run_meta.json
  ...
```

`model_*.pt` — веса и состояние обучения. Завершение 1000 итераций означает
завершение заданного запуска; качество ходьбы проверяется следующим этапом.
При желании открыть графики обучения:

```bash
.venv/bin/tensorboard --logdir logs/mevius2_flat --port 6006
```

Адрес: http://localhost:6006.

## 4. Испытание обученного робота

Для последнего запуска, указанного через `run_name` в конфигурации:

```bash
MPLBACKEND=Agg .venv/bin/python scripts/play.py --config experiments/mevius2.yaml --viewer viser
```

Проверьте строку `Auto-selected checkpoint`: она должна указывать на нужные веса.
Если веса не найдены, исходный скрипт может запустить случайную политику — это
не результат обучения. Для повторяемого испытания указывайте `--checkpoint` явно.

Первое завершённое обучение в этой рабочей копии:

```bash
MPLBACKEND=Agg .venv/bin/python scripts/play.py \
  --config experiments/mevius2.yaml \
  --checkpoint logs/mevius2_flat/2026-10-28_23-18-34_mevius2_flat/model_999.pt \
  --viewer viser
```

Откройте адрес из терминала. При работающем редакторе это обычно
**http://localhost:8082**. Это отдельное окно испытаний с контроллером.
Если уже запущена служба `draft-mevius2-play`, можно пользоваться ею;
перед ручным запуском остановите её командой из следующего этапа.

В **Controls / Commands** задайте команды движения. Проверьте последовательно:
удержание на месте, движение вперёд с небольшой скоростью, изменение скорости
и поворот. Используйте **Play/Pause** и **Reset Environment**.
Запишите команды и длительность испытания, чтобы сравнивать варианты одинаково.

Наблюдайте, следует ли робот командам, падает ли, не скользят ли ноги и не
возникают ли постоянные резкие колебания. Хороший reward сам по себе этих
проверок не заменяет.

## 5. Сохранение нагрузки и метрик

Во время `play.py` автоматически записываются по каждому суставу:

- приложенный момент и угловая скорость;
- пределы момента и скорости;
- время в симуляции и отметки сбросов эпизода.

Для сохранения закончите ручной запуск через **Ctrl+C** в терминале.
Закрытие вкладки браузера не завершает сервер. Если просмотр запущен нами
как служба, используйте:

```bash
systemctl --user stop draft-mevius2-play
```

Рядом с выбранным checkpoint появятся:

- `motor_trace.npz` — числовая запись;
- `motor_curves.png` — рабочие точки моторов относительно границ момента/скорости.

Текущая запись просмотра не содержит полного отчёта о скорости корпуса и
проходимости. Графики обучения и запись приводов — разные результаты.
Полная автоматическая батарея испытаний MEVIUS2 пока не настроена.

Следующий просмотр с тем же checkpoint перезапишет эти два файла при выходе.
Для сравнения испытаний предварительно сохраните запись и график под другим
именем. Это же относится к короткой проверке из этапа 2.

## 6. Расчёт температуры по записи

Для первого обученного контроллера, после завершения просмотра:

```bash
.venv/bin/python scripts/estimate_motor_temperature.py \
  --trace logs/mevius2_flat/2026-10-28_23-18-34_mevius2_flat/motor_trace.npz \
  --config experiments/mevius2_thermal.yaml \
  --output-dir logs/mevius2_thermal/walking_01
```

Для другого запуска замените путь после `--trace`.
Параметры в `experiments/mevius2_thermal.yaml`: питание 48 В, начальная
температура и воздух 25 °C, крепление к дюрали. Напряжение записано как условие;
скрипт не пересчитывает автоматически моторные характеристики при его смене.

Три сценария отличаются предполагаемым теплоотводом. Тепловое сопротивление
0.5/1/2 K/W и теплоёмкость 450 J/K пока не измерены на RS03. Материал крепления
сам по себе не определяет эти коэффициенты: важны размеры, контакт и обдув.

В папке результата:

- `temperature.png` — самая высокая расчётная температура среди суставов во времени;
- `stronger_cooling.csv`, `intermediate.csv`, `weaker_cooling.csv` — температура каждого сустава;
- `assumptions.yaml` — использованные условия и коэффициенты.

Расчёт использует приблизительные потери из статьи и одноузловую тепловую модель.
Температура в ней не снижает момент двигателя и не вызывает отключение.
Нагрев за 10 секунд нельзя выдавать за прогноз часовой работы. Скрипт считает
только записанный интервал; при сбросах эпизода температура не сбрасывается.
Для содержательного сравнения нужна запись устойчивого движения выбранной длительности.

## 7. Что делать с результатами

Сравните варианты на одинаковых командах, времени испытания, условиях среды
и сопоставимом объёме обучения.

| Что наблюдаем | Следующий шаг |
|---|---|
| Робот падает или плохо следует команде | Проверить модель/стойку и качество контроллера; при необходимости продолжить обучение |
| Моторы постоянно близки к границе момента/скорости | Проверить подбор мотора, передаточное отношение, массу и геометрию |
| Предполагаемый нагрев высок | Сравнить менее нагруженную конфигурацию и улучшение теплоотвода; уточнить тепловые коэффициенты |
| Вариант работает лучше по выбранным критериям | Сохранить модель, конфиг, checkpoint, запись нагрузки и тепловой расчёт вместе |

Изменять лучше один параметр или небольшую связанную группу. После изменения
конструкции вернитесь к этапу 2 и обучите/дообучите контроллер для нового варианта.
Для продолжения того же обучения на той же модели поддерживается:

```bash
.venv/bin/python scripts/train.py --config experiments/mevius2.yaml \
  --resume logs/mevius2_flat/2026-10-28_23-18-34_mevius2_flat/model_999.pt
```

Запуск создаст новую папку логов. `max_iterations` задаёт число дополнительных
итераций этого вызова. Продолжение обучения не гарантирует улучшения — сравните
результаты испытаний до и после.

После выбора конструкции следующий инженерный этап — сверить массы, инерции
и параметры привода с реальным роботом и откалибровать нагрев/остывание мотора
на его креплении. Проверку на оборудовании проводят отдельным этапом; веса
симуляционного контроллера сами по себе ещё не являются готовым ПО реального робота.
